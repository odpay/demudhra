demudhra

Your browser already blocks the compromised eMudhra certificates. This removes them from the rest of your machine.

In October 2026, eight eMudhra intermediate CAs turned out to have P-384 private keys that were integers smaller than 256. Anyone can recover them near instantly. Sectigo had cross-signed the same keys, so that's 16 certificates. A commenter on Mozilla's bug counted 107,107 certificates signed with six of those keys logged to CT in under two days, most of them proof-of-concepts for google.com.

Chrome, Firefox and Apple's frameworks block them now (Google, Mozilla, Apple). But curl, git, python3 and anything else that reads its own CA file can still accept them. This finds them by fingerprint and removes them.

curl -fsSL https://demudhra.sh/run | sh

Linux and macOS. Scans, shows what it found, then asks.

What it checks

OS store
Debian, Ubuntu, Fedora, RHEL, Arch, Alpine, SUSE and their relatives. Rebuilt with the distro's own tool, and blocked so a package update can't put the root back.
macOS
/etc/ssl/cert.pem, the file Apple's note tells admins to edit, which curl, git, python3, ruby and openssl read. It drops each cert with its === header line, then re-reads the file to check. A macOS update can put it back, so run it again after updating. Also the system and login keychains, plus Xcode tools, Homebrew, MacPorts and app bundles in /Applications.
Bundles
Java cacerts (every java on PATH, JAVA_HOME, SDKMAN, Gradle and IDE JDKs), Python certifi in venvs, pyenv, pipx, uv and conda, NSS databases for Firefox and Chrome, Node and Ruby bundles, gcloud, AWS and Azure CLIs, editor extensions, and stray curl and OpenSSL PEM files.
Your config
CA files you point at yourself: SSL_CERT_FILE, SSL_CERT_DIR, REQUESTS_CA_BUNDLE, NODE_EXTRA_CA_CERTS and friends, git's http.sslCAInfo, .npmrc, pip.conf, .curlrc and .wgetrc. Read as plain text, never executed.

What it can't fix

Built-in roots
Node, Deno, Bun and Rust programs can carry roots compiled into the binary. It lists the ones it finds with their versions. Update those. Go uses the system store, which demudhra cleans, unless a binary embeds its own roots.
Containers
Images and snaps keep their own copies. Rebuild from updated base images, or wait for the publisher.
Running apps
Anything already running keeps the trust it loaded. Restart it.

Undo

Everything it changes is backed up first, and the run prints the exact command to put it back:

sh ~/demudhra-backups/demudhra-<time>/undo.sh

Flags

--dry-run
report only, never ask
--yes
skip the question
--all-emudhra
{{N_ALL}} instead of {{N_DEFAULT}}: adds the {{N_MORE}} other eMudhra roots and cross-certs, G1 included
--include-aaa
one more: Sectigo's AAA Certificate Services, which Apple lists as optional. Other Sectigo chains can break.

Flags go after sh -s --:

curl -fsSL https://demudhra.sh/run | sh -s -- --dry-run

The default set is {{N_DEFAULT}} certificates: {{ROOT_NAME}} plus the {{N_INTERMEDIATE}} above. Mozilla, Chrome and Apple have all pulled or blocked that root. The full list is {{N_TOTAL}}: those {{N_DEFAULT}}, the {{N_MORE}} that --all-emudhra adds, and AAA. Every fingerprint and its source is on the cert list.
